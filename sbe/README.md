# Official generated SBE C++ microbenchmark

This is SBE 1.35.0 generated code, not a handwritten fixed-layout format labelled SBE. Official artifact URL: https://repo.maven.apache.org/maven2/uk/co/real-logic/sbe-all/1.35.0/sbe-all-1.35.0.jar . Downloaded artifact SHA-256: `d11f4bb7c71322e3538613b2da18b11625be400465b29a09db80bc9785cea3ab`. Java21 executes SbeTool to generate C++ headers from `event.xml`; generated headers are retained in `generated/`. The schema's field named `type` emits a Go-language name warning; this benchmark targets C++ and generation succeeds.

`./build.sh` regenerates and builds two executables and performs correctness checks without benchmark timing. `./run.sh [output_directory]` runs them sequentially and creates raw CSV/logs plus `sbe_summary.csv`. Do not overlap with other benchmark jobs. Inputs default to the sibling `../codec/corpus/` directory, independent of the caller's working directory when using run.sh. Override with `BENCH_CORPUS_DIR=/path/to/corpus ./run.sh /path/to/results`. The build self-check uses this environment variable too, otherwise the sibling default.

Inputs are the exact 4096 changing records exported by the sibling C++ codec benchmark, with five u64 and four u32 business fields plus arbitrary binary payload. Payload lengths:0/64/256/1024, random corpus only. SBE wire size is **68+payload**: standard8B message header,56B fixed root block,4B uint32 varData length,then payload. This adds4B relative to the sibling fixed64+payload format; Protobuf has a different metadata envelope. Header values are schemaId61,templateId1,version1,blockLength56.

Both modes use generated `wrapAndApplyHeader`, field setters, `putPayload`, header decoder, `wrapForDecode` and generated field accessors. Encode copies the pre-existing payload into the output std::string, matching the sibling codec benchmark. Output capacity is reused. The benchmark therefore measures encoding data that already exists as an Event, not a hypothetical application writing directly into its final packet.

`sbe_generated_validated`: generator's normal buffer position checks stay enabled; a small application wrapper verifies minimum68B, schema/template/version, root blockLength and exact payload bounds before field reads. The generated `payloadLength()` itself reads the length prefix before advancing/checking its cursor, so generator default checks alone are not claimed as a complete verifier for hostile bytes. The wrapper supports only this benchmark's schema version and is not a general schema-evolution/fuzzed production decoder. Malformed-header/schema/length smoke checks run outside timing.

`sbe_generated_trusted`: compiled with official `SBE_NO_BOUNDS_CHECK`, disables generator bounds checks and the wrapper. It assumes valid prevalidated wires. It still decodes the standard SBE header and uses its blockLength/version; no schema identity validation occurs in this mode. Never feed it unchecked network input.

decode_all consumes every scalar plus payload length and first/last bytes; it does not scan the entire payload. decode_few consumes id+seq+type only; validated mode also validates the envelope and payload bounds. roundtrip encodes+decode_all. Checksums over every corpus record are compared against independent logical data before timing.

Single-thread CPU0 affinity is required and failure aborts. Warmup8192 operations per repetition; count doubles from4096 until at least20ms batch time or16,777,216 actually executed operations,5 repetitions. The calibration loop always returns the count that produced its elapsed time, including at the cap. Reported med/min/max are over five batch means, not individual-message p99 latency. Data and buffers are reused and hot. Encode/decode entrypoints are noinline and output memory is escaped through a compiler memory barrier. The same virtual interface shape is present as in the sibling benchmark; because this supplementary executable has only one concrete codec, the optimizer may resolve virtual calls where possible. A few nanoseconds of method/dispatch difference should not be interpreted as a format guarantee. Network, DMA, NIC, JVM, Flink, allocation under pressure and queuing are outside scope. No result should be described as zero nanoseconds or used as universal throughput capacity.

Security boundary: `_trusted` is a hot-path lower-bound comparison after external validation. `_validated` includes explicit schema/length checks plus generated bounds checks; their difference is validation policy, not a different SBE format. Neither mode tests live version rollout. A separately fuzzed parser, unknown-field policy, MTU framing and ownership rules remain required for production.

## Valid run and excluded first attempt

The final results contain160 raw rows:80 validated and80 trusted, grouped into32 combinations with5 repetitions each. The four payload/wire pairs are0/68,64/132,256/324 and1024/1092 bytes. Both executables successfully bound their sole benchmark thread toCPU0 (`sched_setaffinity` returned0), completed all independent checksum checks, and ran after transport plus the clean Java/Flink rerun had finished and released the CPU. This is a CPU/memory codec benchmark: **no physical NIC, DPDK, DMA or network traffic is measured**. The summary's median/min/max values are five batch means, never single-message p99 values.

An initial attempt exposed a calibration-cap bug: after timing8,388,608 operations, the original loop could double its count to16,777,216 and terminate without executing that doubled count, then use it as the denominator. The entire initial SBE run was quarantined under`invalid_initial/` and must be excluded from delivery. The timer now tests its stop condition before changing the count, including actually timing the capped count, and all160 rows were rerun. There are25 trusted rows reaching the actual cap and no validated rows reaching it. The sibling codec benchmark owner inspected all1780 existing codec/FlatBuffers-direct/compression rows: none reached that guard, so their already recorded raw measurements were not affected; the source loop was nevertheless corrected for future runs.

No cgroup CPU/throttling before/after snapshots were recorded for the valid SBE run. This field is explicitly`not_recorded` in`results/sbe_measurement_notes.json`; no zero-throttling claim is made. These notes concern only the valid rerun and do not replace the environment record or other benchmark families' measurement notes.
