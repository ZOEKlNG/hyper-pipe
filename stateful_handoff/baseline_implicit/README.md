# 第一版完整基线：隐式子消息＋bytes指针长度setter

这里保留第一轮142配置的冻结源码、原始数据、执行与验证记录；没有删除不符合预期的结果。

它使用Protobuf3.21.12的隐式消息字段`Module tls=3`及`set_text0(ptr,len)`。旧CSV的`P2_parallel_*`标签指普通并列隐式子消息，**不是最终报告中的显式optional**。实际生成代码会在父Clear时delete子对象，bytes API还会产生临时string。最终[API核查](../PROTOBUF_3_21_NOTES.zh-CN.md)已更正该解释。

主矩阵1980行micro、710行pipeline，每配置5次；另210行proto计时、210行独立分配审计、30行存储审计、90行分配器扩展性。完整生命周期验证包括普通/ASan各97场景，以及5组各1000万尝试、实际接收并完整核对41,172,110条。

这些数值仍是本实现的实际测量，但不作为最终PB后端的性能上限，不与新版跨轮吞吐差直接作严格因果比较。最终同一二进制中的P0/P1/P2 × 两种API测试分开验证两项改变。

原始proto的mixed分支有重复TLS刷新，原始CSV保留但不作纯两子消息成本结论；最终版本有只填一次的独立补测。pipeline性能模式的错误计数主要检查槽序与守恒；完整载荷检查来自单独普通/消毒器验证，不能把历史validation键名中的full误读为计时热循环逐条完整解析。

本目录保留原始`run.py`、`build.sh`、CMake和源码哈希。子目录深度与原测量工作区不同，复现请显式给出依赖路径：

```bash
DEP_ROOT="$PWD/../../deps/root" bash build.sh
python3 run.py
```
